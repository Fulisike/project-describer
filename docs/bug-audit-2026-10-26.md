## 静态分析与依赖检查

`/analyze` 的剩余输出包括上游 fmt 浮点缓存索引告警、JSON UTF-8 状态机索引注解告警、spdlog 的 Windows API 注解差异，以及既有 session-loader 局部变量同名告警。已检查相应源码：fmt 的索引依赖指数范围不变量；JSON 状态机使用固定字节类型、状态和查表边界。这些输出未被本次实验确认为可触发缺陷，未直接修改第三方库，也没有把它们计入已修复问题数。后续升级依赖时仍需重跑检查。

本次查阅的 [spdlog 官方安全公告](https://github.com/gabime/spdlog/security/advisories) 和 [nlohmann/json 官方安全公告](https://github.com/nlohmann/json/security/advisories) 页面没有公开公告；这不等于依赖没有漏洞。cxxopts 公告页本次未能获取，因此未作无漏洞结论。未无依据更新或重写已锁定的第三方实现。

Codex 备用指令文件的顺序与路径限制参考了 [官方实现](https://github.com/openai/codex/blob/main/codex-rs/core/src/agents_md.rs)。本工具导出的是本地文件和可读会话清单，不能把该清单当作上游某次请求实际生效的完整模型上下文。

## 验证边界

- 运行验证基于 Windows x64；未在 Linux/macOS、网络共享或特殊文件系统上运行。POSIX 不覆盖提交需要文件系统支持硬链接，失败时会报告错误。
- 未模拟真实磁盘写满、设备拔出或突然断电。显式 close 检查修复了错误处理缺口；原子提交不等于断电后的持久化保证。
- 普通符号链接用例在缺乏 Windows 权限时可能跳过；junction 已另行实测。目录枚举后被恶意并发替换路径的场景不属于本次验证保证，扫描也不是文件系统快照。
- 单文件、单条会话记录和单会话有大小限制，但整个工程的全部文本仍保存在内存中；内存占用随选中文本总量增长。没有新增会静默截断全文导出的全局容量策略。
- TOML 处理只读取本工具需要的顶层备用文件名数组，支持常用的基本/字面字符串和注释，并非完整 TOML 配置解释器。会话读取仍受既有的记录数量、字节预算及上游格式变化限制。
- 现有的隐藏文件、构建目录和已知扩展名过滤策略保留；“检查整个工程”不意味着改变产品默认收集范围。
